# FNG Trader — จำลองซื้อขายตาม Fear & Greed Index

ระบบจำลอง (paper trading) ซื้อ/ขายหุ้น 9 ตัว (SPY, VOO, QQQ, AAPL, MSFT, NVDA, AMZN, GOOGL, BRK-B)
โดยใช้สัญญาณจาก CNN Fear & Greed Index และราคาหุ้นจริงจาก Yahoo Finance
**ทุนจำลองแยกต่อหุ้น ตัวละ 5,000 บาท (รวม 9 ตัว = 45,000 บาท)** — แต่ละหุ้นคือ **1 บัญชีอิสระ (Account ID #1-9)**
มีกระเป๋าเงินสด/พอร์ตของตัวเอง ไม่ปนกัน ซื้อ/ขายครั้งละ 50 บาท ทำรายการแค่ตอนตลาดหุ้นสหรัฐฯ เปิดจริงเท่านั้น
ส่งรายงานเข้า Discord (แบบ Embed สวยงาม) และ Email ทุกวันผ่าน GitHub Actions

## ฟีเจอร์รายงาน

- **ตารางเปรียบเทียบรายวัน** — แสดงทุกหุ้น: รายการวันนี้, จำนวนที่ซื้อสะสม, จำนวนที่ถืออยู่ปัจจุบัน, ต้นทุนเฉลี่ย, ราคาล่าสุด, เงินสด, กำไร/ขาดทุน
- **สรุปยอดถือครองปัจจุบัน** — เรียงหุ้นตามมูลค่าจากมากไปน้อย พร้อมยอดรวมทั้งหมด
- **ผลตอบแทนสะสมรายช่วง** — เทียบมูลค่าพอร์ตวันนี้กับ: เมื่อวาน (รายวัน), ต้นสัปดาห์ (รายสัปดาห์), ต้นเดือน (รายเดือน), ต้นปี (รายปี) — ข้อมูลเก็บสะสมอัตโนมัติใน `data/portfolio_history.csv`
- **Discord Embed** — กล่องรายงานสีเขียว/แดงตามกำไร-ขาดทุนรวม แยกฟิลด์ต่อหุ้นอ่านง่าย แทนตารางข้อความล้วน

## เงื่อนไขการซื้อขาย

| ค่า Fear & Greed | ความหมาย | การกระทำ |
|---|---|---|
| 0–25 | Extreme Fear | **ซื้อทุกวัน** |
| 26–50 | Fear | **ซื้อวันเว้นวัน** |
| 51–75 | Greed | **ขายวันเว้นวัน** |
| 76–100 | Extreme Greed | **ขายทุกวัน** |

- เช็คค่าดัชนี 1 ครั้ง/วัน แล้วสั่งซื้อ/ขายหุ้นทุกตัวที่กำหนดพร้อมกันตามสัญญาณเดียวกัน
- แต่ละหุ้น ทำรายการได้วันละไม่เกิน 1 ครั้ง ครั้งละ 50 บาท
- **เงินทุนแยกต่อหุ้น ตัวละ 5,000 บาท** — ถ้าเงินสดของหุ้นตัวใดตัวหนึ่งหมด จะไม่กระทบหุ้นตัวอื่น (แต่ละตัวมีกระเป๋าอิสระ)
- โซน "วันเว้นวัน" ใช้ state สลับ (toggle) เก็บไว้ใน `data/state.json` เพื่อให้รันต่อเนื่องข้ามวันได้ถูกต้อง

## เงื่อนไขเวลาตลาด (สำคัญ)

ระบบจะ **ทำรายการก็ต่อเมื่อตลาดหุ้นสหรัฐฯ (NYSE) เปิดทำการอยู่จริงเท่านั้น** โดยเช็คแบบละเอียด (`market_hours.py`) ไม่ใช่แค่เช็ควันเสาร์-อาทิตย์:

- ข้าม: วันเสาร์-อาทิตย์
- ข้าม: วันหยุดตลาดสหรัฐฯ (เช่น Thanksgiving, Christmas, New Year, Independence Day ฯลฯ) — ใช้ปฏิทินจริงจากไลบรารี `pandas_market_calendars`
- ข้าม: เวลานอกช่วง 09:30–16:00 น. ตามเวลานิวยอร์ก (จัดการ Daylight Saving Time ให้อัตโนมัติ)
- ป้องกันการรันซ้ำในวันเดียวกัน แม้ workflow จะถูกตั้งให้รันหลายรอบ/วันก็ตาม จะทำรายการแค่ครั้งเดียวต่อวัน
- "วันที่" ที่ระบบใช้อ้างอิงคือวันที่ตามเวลานิวยอร์ก ไม่ใช่วันที่ไทย (ป้องกันความสับสนเรื่อง time zone ต่างกัน)

หากรันตอนตลาดปิด (เช่น กดทดสอบเองในวันเสาร์-อาทิตย์) ระบบจะพิมพ์ข้อความแจ้งเหตุผลแล้วจบการทำงานโดยไม่ทำรายการหรือส่งรายงาน

### ทำไมต้องรันถี่ทุก 15 นาที แทนที่จะตั้งเวลาตายตัว

**ปัญหาที่เจอจริง:** GitHub Actions `schedule` (cron) **ไม่รับประกันว่าจะรันตรงเวลาเป๊ะ** — ช่วงที่ระบบ GitHub มีคิวงานเยอะ อาจดีเลย์การรันได้หลายชั่วโมง (เป็นข้อจำกัดที่ GitHub ประกาศไว้เอง ไม่ใช่บั๊กของโค้ดนี้) ถ้าตั้งเวลาไว้ตายตัวใกล้ช่วงตลาดปิด (เช่นเดิมที่ตั้งไว้ 15:55 น. เวลานิวยอร์ก) แล้วเจอดีเลย์แค่ 1-2 ชั่วโมง ก็จะรันไปตกหลังตลาดปิดพอดี ทำให้ระบบข้ามการซื้อขายไปทั้งวันโดยไม่มีใครรู้

**วิธีแก้ในเวอร์ชันนี้:** ตั้ง cron ให้รันทุก 15 นาที ตลอดช่วง 13:00-21:59 UTC (ครอบคลุมเวลาทำการ NYSE ทั้ง 2 ฤดู DST แบบมีกันชน) วันจันทร์-ศุกร์ แล้วให้โค้ดเช็คเองทุกครั้งว่าตลาดเปิดจริงหรือไม่ และมีระบบกันทำรายการซ้ำ (`has_run_today`) เพื่อให้ทำรายการแค่ครั้งเดียว/วันเท่านั้น แม้จะมีการรัน ~36 ครั้ง/วันก็ตาม — วิธีนี้ไม่ว่า GitHub จะดีเลย์แค่ไหน จะมีรอบใดรอบหนึ่งตกอยู่ในช่วงตลาดเปิดจริงแน่นอน

**ผลกระทบเรื่องโควตา:** แต่ละรอบที่ตลาดปิด (ส่วนใหญ่) จะจบเร็วมาก (~10-15 วินาที เพราะเช็คแล้วข้ามทันที ไม่ต้องดึงราคาหุ้นหรือส่งรายงาน) รวมทั้งวันใช้เวลา Actions ประมาณ 15-25 นาที/วัน (~300-500 นาที/เดือน) ถ้า repo เป็น **Public จะไม่จำกัดเลย** ถ้าเป็น **Private** ยังอยู่ในโควตาฟรี 2,000 นาที/เดือนสบายๆ

## วิธีติดตั้ง

1. ทดสอบรันในเครื่องตัวเอง
   ```bash
   pip install -r requirements.txt
   python main.py
   ```

2. อัปโหลดขึ้น GitHub (repo ใหม่ แยกจากโปรเจกต์เดิม — ดูคำตอบข้อ 7 ด้านล่าง)

3. ตั้งค่า **GitHub Secrets** (Settings → Secrets and variables → Actions → New repository secret):
   - `DISCORD_WEBHOOK_URL` — Webhook URL ของช่อง Discord
   - `SMTP_USER`, `SMTP_PASSWORD` — บัญชีอีเมลผู้ส่ง (ถ้าใช้ Gmail ต้องสร้าง App Password)
   - `EMAIL_FROM`, `EMAIL_TO` — อีเมลต้นทาง/ปลายทาง (ปลายทางคั่นด้วย `,` ได้หลายคน)
   - (ถ้าใช้ SMTP เจ้าอื่น) `SMTP_HOST`, `SMTP_PORT`

4. ตรวจสอบว่า workflow มีสิทธิ์ push กลับเข้า repo ได้:
   Settings → Actions → General → Workflow permissions → เลือก **Read and write permissions**

5. Workflow จะรันอัตโนมัติทุกวันตามเวลาที่กำหนดใน `.github/workflows/daily-trading.yml`
   (ค่าเริ่มต้น 23:00 UTC = 06:00 น. เวลาไทย) หรือกดรันเองได้ที่แท็บ **Actions → Run workflow**

## ข้อ 7: มีโปรเจกต์รันอยู่ 1 ตัวแล้ว รันอีก 1 โปรเจกต์บน GitHub ได้ไหม?

**ได้ครับ ไม่มีปัญหา** GitHub Actions ทำงานแยกอิสระ "ต่อ repository" และ "ต่อ workflow file"
ไม่ได้จำกัดว่าบัญชีหนึ่งรันได้แค่ 1 โปรเจกต์ สิ่งที่ต้องรู้:

- **แนะนำให้แยก repo ใหม่** สำหรับโปรเจกต์นี้ (เช่น `fng-trader`) จะดูแลง่ายและไม่ชนกับโปรเจกต์เดิม
- ถ้าจะใส่ไว้ใน repo เดิม ก็ทำได้เช่นกัน แค่เพิ่มไฟล์ workflow ที่สอง (เช่น `.github/workflows/daily-trading.yml`)
  ต่างจากไฟล์ workflow ของโปรเจกต์เดิม — GitHub รันแต่ละไฟล์ workflow แยกกันเอง ไม่ทับซ้อนกัน
- ข้อจำกัดที่ต้องระวังคือ **โควตานาทีรันฟรีของ GitHub Actions ต่อบัญชี** (ไม่ใช่ต่อโปรเจกต์)
  - บัญชี Free: ~2,000 นาที/เดือน (สำหรับ private repo; repo แบบ public ไม่จำกัด)
  - งานนี้รันแค่ไม่กี่นาที/วัน (~1-2 นาที) จึงใช้โควตาน้อยมาก แม้จะมีหลายโปรเจกต์รันพร้อมกันก็ไม่น่ามีปัญหา
- แต่ละ repo/workflow มี Secrets แยกกันเป็นอิสระ ตั้งค่าซ้ำได้ไม่กระทบกัน

สรุป: สร้าง repo ใหม่แยกต่างหากสำหรับโปรเจกต์นี้ได้เลย จะรันคู่ขนานกับโปรเจกต์เดิมได้สบายๆ

## ข้อควรระวัง

- Endpoint ของ CNN Fear & Greed Index (`production.dataviz.cnn.io`) เป็น endpoint ไม่เป็นทางการ
  อาจถูกเปลี่ยนแปลงหรือบล็อกโดย CNN ได้โดยไม่แจ้งล่วงหน้า ถ้าดึงข้อมูลไม่ได้ควรมีระบบแจ้งเตือนแยก (เช่น ส่งข้อความ error เข้า Discord ด้วย)
- เป็นระบบ **จำลอง (paper trading)** เท่านั้น ไม่ได้เชื่อมต่อกับโบรกเกอร์จริง ไม่มีการซื้อขายหุ้นจริงเกิดขึ้น
- ควรทดสอบรันด้วยมือ (`workflow_dispatch`) ก่อน 2-3 ครั้ง เพื่อตรวจสอบว่า Secrets และ logic ทำงานถูกต้อง ก่อนปล่อยให้รันอัตโนมัติทุกวัน
